# SEC-001: Ironclad Verification for Security-Critical Paths

## The Principle
Security-critical operations (Genesis ceremonies, key recovery, signing delegations) MUST NOT rely solely on in-process unit tests or mocked functional tests. 

## The Debacle: The "Mocking Paradox"
The Genesis failure of Phase 25.2 occurred because functional tests using `unittest.mock` succeeded while the real-world CLI crashed due to a `NameError` in a branch reached only by real hardware APIs. The mocks "shadowed" the real execution environment.

## Mandatory Implementation
1. **Zero-Mock E2E**: Any function exposed as a `tt` security ritual must have a corresponding "Ironclad" test using `subprocess.Popen` to interact with the REAL binary.
2. **Environment Parity**: Tests must verify real OS-level interactions (Keychain, filesystem persistence, standard error streams).
3. **Traceback Zero-Tolerance**: Any occurrence of `Traceback`, `NameError`, or `AttributeError` in the stderr of a security command is a CRITICAL FAILURE, even if the exit code is 0 (caught by a top-level broad except).
