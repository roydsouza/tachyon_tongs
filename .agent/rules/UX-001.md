# UX Governance & Interface Protocol (UX-001)

## Philosophy
The Tachyon Tongs interface is the "Single Pane of Glass" into the forensic substrate. To ensure consistency, safety, and forensic integrity, every UX modification must follow a strict architectural and documentation loop.

## Constraints

### 1. Pre-Implementation Ritual (Read-Only)
Before writing any UI/UX code or proposing changes:
- **Architecture Sync**: You MUST read `docs/INTERFACES.md` to align with established design principles (Ambient Awareness, Progressive Disclosure, Zero-Latency Control).
- **Status Audit**: You MUST review the current implementation status in `TASKS_INTERFACES.md`.
- **Task Alignment**: If the task is not already in `TASKS_INTERFACES.md`, you MUST add it first as a priority item.

### 2. Execution Protocol (The TDAD Loop)
- **Modular First**: Interface components must be decoupled from core agent logic.
- **Regression Testing**: Add regression tests to `tests/integration/test_interfaces.py` for every new UI manifold or control.
- **Signed ADRs**: Any significant UX architectural change (e.g., new TUI view, new remote bridge protocol) requires a signed ADR.

### 3. Post-Implementation Alignment (Sync)
Upon task completion:
- **Master Record Sync**: Update `TASKS_INTERFACES.md` with the execution results and mark as complete.
- **Documentation Sync**: Update `docs/INTERFACES.md` to ensure the "Current Implementation" section reflects the actual state of the substrate.
- **Forensic Checkpoint**: Re-sign all documentation using `scripts/forensics/resign_docs.py` and push to GitHub.

---
> [!IMPORTANT]
> Failure to update `docs/INTERFACES.md` after a UX change is a "Documentation Drift" violation.
